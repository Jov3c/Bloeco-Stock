## 本轮执行规则

1. 先执行所有当前能运行的 P0/P1 自动化，再补缺失的 Bot 或 Paper 集成场景。
2. 每个缺陷保留“复现失败 → 最小修复 → 回归通过”的证据；不以绕过测试代替修复。
3. 未实现需求保持 `未实现`，不会以文案、占位 GUI 或测试跳过伪装成交付。
4. 外部插件适配必须记录插件版本和 API 可用性；没有实际插件包时只能标记 `外部兼容待验`。

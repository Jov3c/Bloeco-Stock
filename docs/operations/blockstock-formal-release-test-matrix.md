# BlockStock 正式发布测试矩阵

## 目的与发布规则

本矩阵是 BlockStock 的唯一正式验收清单。每个用例必须保留其自动化输出、服务器日志或人工录屏；未执行、跳过或环境不满足均不能记为通过。

发布门禁分为三个等级：

| 等级 | 含义 | 发布要求 |
| --- | --- | --- |
| P0 | 资金、股份、权限、数据完整性或玩家主流程 | 必须全部通过 |
| P1 | 主要玩法和第三方兼容 | 必须通过；不支持的外部插件需明确标为“不适用” |
| P2 | 文案、边界体验和性能观察 | 不得存在阻断性问题 |

统一环境：Paper 1.21.4、Java 21、Vault、EssentialsX、SQLite；所有 Bot 只能连接隔离的 `127.0.0.1:25566`，禁止接触玩家正式服 `25565`。货币按最小单位保存，所有交易和资金断言以数据库及 Vault 托管余额为准。

状态含义：`已通过` 表示本次发布候选已经实际执行；`已有自动化、待执行` 表示脚本/单测存在但本次尚未以正式门禁执行；`待补自动化` 表示必须新增脚本或集成夹具；`人工兼容` 表示需要真实第三方插件 API 和受控服务器。

## 已确认的功能边界

本次源码审查确认：公司创建、原生资产、IPO、证券账户、二级市场、十家蓝筹、蓝筹事件、蓝筹分红、公开行情与公告查询已有实现；但 GOV-001 至 GOV-005 中标为“功能未实现”或“部分实现”的项目不能通过补测试变成可交付功能。它们必须先完成业务、数据迁移、权限/GUI 和恢复账本设计，再进入本矩阵的自动化验收。

## 执行顺序与合格判定

1. 每次候选包先运行 `gradlew test shadowJar --rerun-tasks --no-daemon`，并保存 JUnit XML。
2. 在空的隔离 Paper 数据目录跑 P0 Bot/集成测试；每个场景使用独立玩家 UUID，禁止复用正式库。
3. 执行故障恢复、账本对账和升级夹具；最后停止服务器再做 SQLite 只读核验。
4. 在每一种实际安装的可选插件组合中执行对应人工兼容项，记录插件版本和录屏。
5. 只有所有 P0 通过、所有适用 P1 通过、无未解释 P2 阻断项、正式服备份可恢复时，才能标记“正式版”。

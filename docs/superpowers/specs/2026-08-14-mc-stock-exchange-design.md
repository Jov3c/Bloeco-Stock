# MC 公司证券交易所：产品设计

## 1. 定位与范围

这是一个只安装在 Paper 服务端的 Minecraft 插件。它将已有服务器经济、领地、商店、产线和任务玩法，转化为玩家公司可验证的经营数据，并提供易理解的股票交易和分红玩法。玩家客户端无需安装模组或资源包。

产品目标是“经营驱动的轻量股市”：交易规则接近现实交易所，但操作只保留创建公司、绑定资产、IPO、买卖股票、查看行情、领取自动分红和参与少数重大投票。

首发不包含融资融券、做空、期权、复杂技术指标、董事会多层级审批、拆股或复权计算。

## 2. 平台与插件兼容策略

运行平台为 Paper；经济结算通过 Vault 对接服务器现有货币实现（推荐 EssentialsX Economy）。核心以稳定的内部“经营事件”接口工作，插件适配器只负责将外部事件转换成统一流水，避免核心依赖某一个商店或领地插件。

首发适配目标：

| 类别 | 优先适配 | 作用 |
| --- | --- | --- |
| 经济 | Vault、EssentialsX Economy | 扣款、成交收款、分红、公司金库与托管结算 |
| 领地 | Towny、Lands、GriefPrevention、Residence | 注册地址、资产归属、地块成本与税费 |
| 玩家商店 | Shopkeepers、QuickShop-Hikari、ChestShop | 识别公司店铺及其真实玩家成交 |
| GUI 商店 | EconomyShopGUI | 默认不作为营业收入；可选记录为采购成本或服务器订单 |
| 委托/任务 | Quests、BetonQuest、Jobs Reborn | 公司发布、金库支付的任务与奖励 |
| 产线 | Slimefun、ItemsAdder/Oraxen 生态及原版产线 | 登记公司产出；只有在绑定店铺实际售出后才产生收入 |

其他插件以适配包或管理员配置的事件映射接入。不存在可验证交易归属的插件，不应自动计入财报。

## 3. 主要对象与权限

### 公司

公司拥有注册资本、公司金库、绑定资产、股份、财报和状态。状态为：筹备中、上市、退市收购中、清算中、已退市。

### 人员

创始人可管理公司的资产绑定、职务授予、IPO、增发提案和主动退市申请；不可直接提走金库资金。可选职务为店长（管理店铺和产线）、财务（查看账目和管理获授权的工资）、任务管理员（发布公司委托）。工资必须由公司金库按管理员配置的上限支付。

### 股东

股东可交易、查看公开财报、领取自动分红、并对增发提案投票。持股决定投票权；投票快照在提案开始时冻结，防止临时买股影响已开始的投票。

## 4. 公司创建与 IPO

1. 创始人支付创建费和最低注册资本，注册唯一公司名称。
2. 绑定至少一个有效领地或经营资产，完成公司激活。
3. 每家公司初始固定为 1,000 股；公开发售比例限定在 30%--70%。
4. 系统以注册资本和已绑定资产评分计算基准价；创始人只能在基准价的正负 20% 内设定 IPO 价格。
5. IPO 认购所得直接进入公司金库；未公开发售的股份由创始人持有。

这些限制避免以天价空气股融资，同时让创建人保留合理的发行策略。

## 5. 交易所

### 交易规则

交易所采用统一订单簿，价格优先、时间优先撮合。首发支持限价买入、限价卖出和撤单；不支持市价单、做空或杠杆。买方挂单时锁定所需货币，卖方挂单时锁定股份；取消或未成交部分立即返还。

成交收取 1% 手续费，进入交易所补偿基金会。手续费不销毁，不参与普通分红。

### 行情界面

`/stock` 提供公司列表和股票详情：分时线、日 K 线、成交量、最新价、涨跌幅、买卖五档、近 7 天净利润、上次分红和下次结算倒计时。界面不用技术指标或专业金融术语。

`/portfolio` 显示玩家持仓、成本、市值、挂单、待收分红和历史成交。

## 6. 公司财报与分红

每个公司资产必须显式绑定；同一资产同一时间只能属于一家公司。适配器写入不可修改的经营流水，至少包含来源插件、外部交易 ID、公司和资产 ID、买卖双方、金额、时间与分类。

### 计入净利润

- 公司绑定店铺向真实玩家售出的收入；
- 公司承接并完成、奖励直接进入公司金库的任务/委托收入；
- 公司绑定产线的产物，经绑定店铺实际售出的收入；
- 已绑定经营资产发生的进货、向玩家发布的任务奖励、领地税费和手续费，作为成本扣除。

### 不计入净利润

- `/pay`、管理员发放、普通玩家转账；
- 无限库存的系统商店销售额；
- 资产绑定前的历史交易；
- 同账号、关联账号或被风控规则标记的循环交易。

结算周期为 7 天。正净利润按公司 IPO 时锁定的 30%、50% 或 70% 分红档位，自动打入结算时持股玩家的 Vault 账户；余下部分留在金库。亏损时本期不分红。公司详情展示近 7 天收入、成本、净利润、金库、已绑定资产和分红历史。

## 7. 增发

公司可增发，但必须由股东批准：

- 每次最多增发当前总股数的 20%，每 30 天最多一次；
- 定价不得低于近 7 天成交均价的 90%；
- 提案投票期为 48 小时；
- 参与投票股份至少达到流通股的 20%，赞成票须超过参与票的三分之二；
- 通过后新股按增发价在交易所认购，募集资金进入公司金库；未售完的新股自动取消。

## 8. 退市与补偿

主动退市采用现金收购：创始人必须预先将收购款存入托管，再按过去 7 天成交均价、且不低于管理员配置的保护价回购全部流通股。完成收购后股票退市。

强制退市适用于达到管理员配置的“连续亏损且无有效经营活动”阈值的公司。公司进入清算，先按持股比例分配金库余额；若不足，交易所基金会在金额、持有期和单公司额度上限内提供补偿。基金会不会为投机交易无限兜底。

## 9. 风控与审计

所有订单、成交、流水、分红、投票、增发、收购和清算都保留审计记录。管理员可配置最低在线时长、交易冷却、单日交易额度、关联账号拦截、异常成交告警和插件适配开关。

管理者无法绕过金库提款；只有已验证经营事件可构成财报收入。这两点是防止虚假营收、卷款与利用补偿基金套利的基础。

## 10. 玩家核心流程

```text
创建公司 -> 绑定领地/店铺/产线/委托 -> IPO -> 经营并形成可验证流水
     -> 股票交易 -> 每 7 天自动结算与分红 -> 增发投票或退市清算
```

三个入口：

- `/company`：创建公司、资产绑定、金库、财报和管理操作；
- `/stock`：行情、K 线、盘口、下单和撤单；
- `/portfolio`：个人持仓、挂单、分红和成交历史。

## 11. 管理员配置

管理员可配置创建费、最低注册资本、资产评分、IPO 价格范围、分红档位、结算日、手续费、基金补偿上限、增发上限、投票门槛、退市阈值、反刷规则以及各适配器启用状态。默认值应针对服务器实际通货膨胀和玩家在线规模在测试服校准后再发布。

## 12. 非目标与后续版本

后续可评估：更多插件适配器、公告与新闻、公司评级、股东治理扩展、配股与拆股。首发不承诺自动支持没有公开 API 或无法识别交易归属的插件。

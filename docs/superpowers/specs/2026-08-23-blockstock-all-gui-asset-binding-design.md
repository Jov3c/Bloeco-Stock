# BlockStock 全 GUI 与可选资产绑定设计

## 目标

将普通玩家流程收敛为唯一入口 `/stock`：公司创建、公司管理、资产绑定、IPO、认购和二级交易均使用原版库存 GUI。外部领地/商店插件增强资产验证与自动收益读取，但不是创建公司或上市的前置安装条件。

## 支持层级

| 层级 | 资产类型 | 是否要求外部插件 | 能否上市 | 自动读取收益 |
|---|---|---:|---:|---:|
| 原生 | BlockStock 原生经营资产 | 否 | 是 | 否，初始为零，后续由原生任务/产线接入 |
| 领地 | Lands、Residence 领地 | 是 | 是 | 读取领地内已接入来源 |
| 商店 | QuickShop、Shopkeepers 商店 | 是 | 是 | 读取已接入的成交收益 |

原生资产只能由公司创建者通过 GUI 创建和确认，绑定记录明确标示“未接入自动收益”，防止玩家误以为它能凭空产生利润。外部插件未安装时，相关图标灰显并说明原因，不影响原生资产和 IPO。

## GUI 流程

1. `/stock` 首页增加“公司中心”。
2. 公司中心列出：创建公司、我的公司、资产管理、IPO、公告、财报、治理；无公司时只显示创建入口。
3. 创建向导依次使用原版 GUI 输入公司名、实缴资本，点击分红比例，最后确认扣款。
4. 资产管理页显示已有资产与“绑定新资产”：
   - 原生资产：输入名称，确认建立归属为创建者的 BlockStock 原生资产。
   - 已安装适配器：选择 Lands / Residence / QuickShop / Shopkeepers，再从其 API 返回的本人资产列表中选择；列表异常或过长时使用带校验的原版铁砧搜索。
5. IPO 向导输入募资目标、发行价并确认；沿用现有规则：目标不超过实缴资本五倍，公告十二小时后开放、认购两天。
6. 认购、查询和交易继续留在同一 GUI；文字命令保留给管理员恢复和兼容性排障，不作为普通玩家流程。

## 适配器架构

现有 `CompanyAssetAdapter` 扩展为两个可选能力：

- `AssetCatalogAdapter`：在主线程读取插件 API，返回已验证且属于当前玩家的匿名安全展示项（外部 key、展示名、类型）。
- `RevenueSourceAdapter`：在插件能够提供成交/收益事件时把聚合收入写入公司财务；不具备稳定收入 API 的适配器只做归属验证，不伪造收益。

所有适配器以 `softdepend` 和运行时注册方式加载；缺失、版本不兼容或 API 出错时自动不可用且不影响 BlockStock 启动。反射仅作为“检测插件是否存在”的隔离层，核心验证调用官方公开 API；不读取插件私有数据文件。

## 第三方插件安装边界

- Lands 的官方开发文档提供 `LandsAPI` 集成入口。
- Residence 的官方仓库提供 Maven/JitPack API，并将预编译版本作为独立发行。
- Shopkeepers 提供当前 Paper 兼容发行与公开变更记录。
- 这些插件的具体二进制发行、许可和下载渠道由其作者控制。BlockStock 将先完成软依赖适配；需要授权下载的 JAR 只能在服务器所有者提供已获许可的文件后安装，不能绕过许可或账户限制。

## 安全和验证

- GUI 只显示请求者拥有的资产；每次确认前再次调用适配器验证归属。
- 原生资产的 owner 固定为创建者；公司转让前不允许无审计的绑定替换。
- 绑定、IPO、资金和订单均经过既有异步服务和主线程门禁；确认页之前无副作用。
- 外部插件卸载后绑定保留历史记录但标示“来源不可用”；已上市公司不会因插件临时缺失而自动退市，自动收入暂停并在财报标记。

## 验收

- 无任何外部资产插件时，玩家可用 GUI 创建原生资产、完成 IPO 并进入市场。
- 每个已安装且可用的适配器只列出该玩家拥有的资产；伪造外部 key 或换人确认被拒绝。
- 外部插件缺失/失效不会阻止插件启动、不会泄露他人资产、不会改动已绑定资产或资金。
- 普通玩家无需输入公司、资产、IPO、认购或交易文字命令。
- 单元测试覆盖原生归属、适配器缺失、二次归属验证、会话过期和确认前零副作用；完整构建与 Paper 启动验证通过。

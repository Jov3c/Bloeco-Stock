# BlockStock 原版交易所 GUI 设计

## 目标

在不要求客户端安装模组、资源包或额外插件的前提下，为 BlockStock 提供中文、可视化且防误操作的原版库存 GUI。GUI 是既有资金账本、委托撮合与恢复门禁的安全入口，不复制或绕过任何金融业务规则。

## 范围与非目标

- 玩家执行 `/stock` 或 `/stock gui` 打开交易所主菜单；`/stock help` 保留完整文字帮助，现有文字子命令继续兼容。
- 本阶段覆盖市场浏览、股票详情与五档盘口、资金账户、持仓、我的委托、成交记录、买入、卖出、撤单和资金转入/转出。
- 不在 GUI 中实现 K 线、分时图、公司创建、资产绑定、公告编辑或 IPO 认购；这些保持原命令入口，后续可作为独立界面迭代。
- 不引入客户端模组、ProtocolLib、资源包或第三方 GUI 库。

## 方案比较与选择

1. 纯文字命令：实现最少，但用户明确认为不好看，且不适合浏览盘口与委托。
2. 箱子 GUI 加聊天输入：实现简单，但下单时跳回聊天会破坏统一体验。
3. 原版箱子 GUI 加铁砧输入与确认页：所有浏览、数量/价格录入和最终确认均留在原版界面中；使用稳定的 Bukkit/Paper 库存事件，客户端零安装。

采用方案 3。铁砧界面只收集一项文本；实际资金变更和下单仅发生在随后点击绿色“确认执行”后。

## 界面与导航

### 主菜单（6 行箱子）

固定入口为：市场、资金账户、我的持仓、我的委托、成交记录、IPO 指引、文字帮助和关闭。无权限入口使用灰色物品展示原因；点击时仍再次校验权限。数据项加载期间显示时钟和“正在加载”。

### 市场与股票详情

市场页每页至多 45 家上市公司，显示代码、公司名、最新价、日涨跌、成交量和市值；前后页与返回键固定在底行。点击公司打开详情页。

详情页显示公开行情与五档买盘/卖盘。买入和卖出按钮进入各自的下单草稿；刷新、返回市场和关闭为固定操作。盘口只展示已聚合的匿名档位，不泄露委托人或订单 ID。

### 个人页面

资金页显示证券账户可用/冻结资金，并提供转入、转出按钮。持仓页仅展示当前玩家的持仓。委托页仅展示当前玩家的未完成和历史委托；每张可撤销委托提供撤单入口。成交记录同样只展示当前玩家的成交，不显示对手方。

### 原版输入与确认

所有需要数值的动作使用一个原版铁砧输入界面，预填中文占位文本。输入规则：金额必须是正数且符合服务器货币精度；股数必须是正整数；股票代码由详情页固定带入，不能由玩家在输入中替换。

买入/卖出依次输入股数和限价，资金转入/转出输入金额，撤单无需输入。进入确认页后展示方向、代码、股数、限价，以及买入的最大冻结金额提示。绿色羊毛为确认，红色羊毛为取消。关闭、返回或取消不会产生调用。

## 安全、并发与恢复

- 每个打开的库存 GUI 由玩家 UUID 和随机会话标识绑定；异步查询完成后只更新仍在线、仍处于同一会话的玩家。
- 所有 Bukkit/Paper 物品与库存操作回到 `MainThreadExecutor`；SQL/服务查询继续使用现有异步 `CompletionStage`。
- 任何点击、拖拽、热键交换和双击收集都取消，展示物品不能被拿走或移动。
- GUI 每次动作重新检查玩家在线状态、既有权限、初始化状态和 `mutationsOpen`。恢复/维护期间只允许只读浏览；资金与交易操作给出中文不可用提示。
- GUI 不持有余额或订单真相：转入、转出、下单、撤单只调用现有 `SecuritiesCashService` / `SecondaryMarketService`，由既有事务、Vault saga 与恢复流程执行。
- 服务返回后以中文结果消息反馈，并刷新相关页面；失败仅显示通用错误，不暴露异常、SQL、其他玩家数据或可撤单 UUID。

## 代码边界

- 新增 `paper` 层 GUI 控制器、会话/页面模型、库存物品工厂和监听器；Bukkit 类型不得进入 application/domain。
- 现有 `StockCommand` 仅路由 `/stock` 与 `/stock gui` 到 GUI；其它子命令保持行为不变。
- `BlockecoPlugin` 注册 GUI 监听器并将已构建的查询、交易、资金、主线程、消息和门禁依赖注入。
- 必要的 GUI 文案集中在 `Messages` / `config.yml`，默认中文且可配置。

## 验收与测试

- 无客户端安装时，玩家能以 `/stock` 打开主菜单并经按钮浏览市场、资金、持仓、委托和成交。
- 只读页面的数据异步返回后只更新正确且仍有效的会话。
- 私有持仓、委托与成交不会出现在其他玩家页面，盘口不含身份信息。
- 所有交易动作在确认前不调用业务服务；取消、关闭或过期会话不产生资金/订单变动。
- 恢复维护、缺权限、离线和服务异常路径安全关闭或提示，且库存物品不可被取得。
- 单元测试覆盖导航、页码边界、会话过期、权限/维护门禁、确认前无副作用和确认后服务调用；完整 Gradle 测试与本地 Paper 启动通过。

## Paper 兼容性依据

实现基于项目当前的 Paper `1.21.4-R0.1-SNAPSHOT`。库存点击处理遵循 `InventoryClickEvent` 的事件模型；铁砧输入使用 `PrepareAnvilEvent`；异步服务回调按照 Paper 调度指南切回主线程后再接触 Bukkit 对象。

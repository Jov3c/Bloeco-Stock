# Blockeco 实施路线图

本路线图将已确认的产品设计拆成六个可独立验收的子项目。每个阶段开始前单独生成详细实施计划，并根据当时的 Paper 与第三方插件官方 API 重新核实依赖版本。

## 技术基线

- 服务端：Paper，首个兼容基线为 1.21.4；只使用稳定 Bukkit/Paper API，不使用 NMS。
- 字节码：Java 21。可运行在 Java 21 及更高版本；针对更新 Paper 版本另做运行测试。
- 构建：Gradle Kotlin DSL、Shadow 打包、JUnit 5。
- 存储：SQLite 为默认单服存储；交易所阶段增加 MySQL/MariaDB 后端。
- 金额：领域层使用整数最小货币单位，只有 Vault 边界转换为 `double`。
- UI：原版 Inventory GUI、Adventure/MiniMessage；玩家客户端不安装模组或资源包。

## 阶段拆分

1. **核心基础与公司注册**：插件骨架、Vault、SQLite、公司领域模型、公司金库、注册补偿事务、审计与基础命令。
2. **经营资产与财报流水**：统一适配器 SPI、资产唯一绑定、Towny 与 Shopkeepers 首发适配、经营事件去重、收入/成本分类。
3. **交易所与行情**：IPO、限价订单簿、价格/时间优先撮合、资金和股票冻结、成交手续费、分时线、日 K、成交量、五档盘口。
4. **周期结算**：7 天财务期、30%/50%/70% 锁定分红、补偿基金会账本、定时任务与离线玩家结算。
5. **治理和退市**：增发提案、持股快照、48 小时投票、托管回购、强制清算、有限补偿与管理员处置界面。
6. **兼容扩展和运营工具**：ChestShop、Lands、GriefPrevention、Residence、Quests、BetonQuest、Jobs Reborn、Slimefun 等适配器，以及异常成交告警、数据导出和性能压测。

## 适配优先级依据

- Towny 和 Shopkeepers 均提供公开的开发 API，是首轮领地与玩家商店适配目标。
- ChestShop 作为第二个商店适配器，以其公开交易事件为接入点。
- QuickShop-Hikari 的仓库声明限制 AI 系统分析和使用其项目内容，因此不在 AI 辅助开发的首发适配范围。只有在取得明确许可，或存在不受该限制且足够完成接入的正式公开 API 文档后，才进入实施计划。
- 对不存在稳定 API、无法证明交易归属或许可证不允许的插件，只保留 Blockeco 的通用适配器 SPI，不读取其内部类或数据库。

## 阶段验收原则

每个阶段必须同时满足：领域单元测试通过、SQLite 集成测试通过、Paper 测试服加载成功、核心异常路径有审计记录、服务器重启后状态一致。涉及货币和股份的步骤必须先验证失败恢复，再进入下个阶段。
